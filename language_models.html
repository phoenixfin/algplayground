Language models — tokens, sampling & anatomyModel bahasa — token, sampling & anatomi

A large language model does one thing: given the text so far, output a probability for every possible next token, pick one, append it, repeat. This page opens up the three ends of that loop — how text becomes tokens, how a distribution becomes a choice, and what a transformer's parameters actually are.

Model bahasa besar hanya melakukan satu hal: diberi teks sejauh ini, keluarkan probabilitas untuk setiap token berikutnya, pilih satu, tambahkan, ulangi. Halaman ini membuka tiga ujung dari putaran itu — bagaimana teks menjadi token, bagaimana distribusi menjadi pilihan, dan apa sebenarnya parameter sebuah transformer.

Start from letters; keep gluing the most common pairMulai dari huruf; terus rekatkan pasangan paling umum

Models don't read letters or whole words, but tokens — chunks learned from data. Byte-pair encoding begins with single characters and repeatedly merges the most frequent adjacent pair into a new symbol. Common words become one token; rare words fall apart into reusable pieces, so nothing is ever "unknown". Edit the text, then slide through the merges.

Model tidak membaca huruf atau kata utuh, melainkan token — potongan yang dipelajari dari data. Byte-pair encoding mulai dari karakter tunggal dan berulang kali menggabungkan pasangan bersebelahan yang paling sering menjadi simbol baru. Kata umum menjadi satu token; kata langka terurai menjadi potongan yang bisa dipakai ulang, sehingga tak ada yang "tak dikenal". Sunting teksnya, lalu geser melewati penggabungan.

Try this
  1. Press +1 merge a few times: the first rules glue letter pairs that are everywhere ("e" + "r", "w" + "e" …).
  2. Slide to the end: frequent words ("low", "new") are single tokens; test lowering — an unseen word is built from known pieces like "low" + "er" + "i" + "n" + "g".
  3. Paste a different language or gibberish: it tokenizes into many more pieces. That is why some languages cost more tokens per sentence.
Coba ini
  1. Tekan +1 gabung beberapa kali: aturan awal merekatkan pasangan huruf yang ada di mana-mana ("e" + "r", "w" + "e" …).
  2. Geser ke ujung: kata sering ("low", "new") menjadi satu token; uji lowering — kata yang belum pernah dilihat dibangun dari potongan yang dikenal seperti "low" + "er" + "i" + "n" + "g".
  3. Tempel bahasa lain atau teks acak: ia terpecah jadi jauh lebih banyak potongan. Itulah sebabnya sebagian bahasa memakan lebih banyak token per kalimat.

A distribution is not a decisionDistribusi bukan keputusan

A transformer outputs a probability for each token; decoding turns that into one choice. Temperature sharpens or flattens the distribution, top-k keeps only the k likeliest tokens, top-p keeps the smallest set whose probabilities add to p. Here the "model" is a tiny word-count table (an n-gram) trained on a toy corpus — nothing like GPT in power, but the decoding knobs act on any model's probabilities in exactly the same way.

Transformer mengeluarkan probabilitas untuk tiap token; decoding mengubahnya menjadi satu pilihan. Temperatur menajamkan atau meratakan distribusi, top-k hanya menyimpan k token paling mungkin, top-p menyimpan himpunan terkecil yang probabilitasnya berjumlah p. Di sini "model"-nya hanyalah tabel hitung kata mungil (n-gram) yang dilatih pada korpus mainan — jauh dari GPT dalam kemampuan, tetapi kenop decoding bekerja pada probabilitas model mana pun dengan cara yang sama persis.

Try this
  1. Prompt "the cat", τ = 1, and press sample 1 repeatedly: different continuations each time. Press greedy: always the single likeliest word — and soon a repetitive loop.
  2. Drop τ to 0.2: the distribution collapses onto the top token (like greedy). Raise to 3: it flattens towards uniform, and the text turns to nonsense.
  3. With τ = 1.5, set top-p = 0.5 or top-k = 3: the long tail of silly words is cut off — that is how chat models stay creative without going off the rails.
  4. Set context to 0 words: pure word-frequency babble. Raise it to 3: the output copies the corpus because the model has memorised it.
Coba ini
  1. Prompt "the cat", τ = 1, lalu tekan sampel 1 berulang kali: lanjutan berbeda tiap kali. Tekan greedy: selalu satu kata paling mungkin — dan segera menjadi putaran berulang.
  2. Turunkan τ ke 0,2: distribusi runtuh ke token teratas (seperti greedy). Naikkan ke 3: mendatar ke arah seragam, dan teks menjadi omong kosong.
  3. Dengan τ = 1,5, atur top-p = 0,5 atau top-k = 3: ekor panjang kata-kata konyol terpotong — begitulah model chat tetap kreatif tanpa melantur.
  4. Atur konteks 0 kata: ocehan murni berdasar frekuensi kata. Naikkan ke 3: keluarannya menyalin korpus karena model telah menghafalnya.

A transformer is one block, stacked L timesTransformer adalah satu blok yang ditumpuk L kali

Every "7B" or "70B" is just arithmetic on a handful of numbers: width d, depth L, vocabulary V. Set them and see where the parameters live, how much memory the weights need, and how large the "KV cache" (the keys and values remembered for each past token) gets as the context grows. Presets match published configurations.

Setiap "7B" atau "70B" hanyalah aritmetika pada beberapa angka: lebar d, kedalaman L, kosakata V. Aturlah dan lihat di mana parameter berada, berapa memori yang dibutuhkan bobotnya, dan seberapa besar "KV cache" (key dan value yang diingat untuk tiap token lampau) saat konteks tumbuh. Rules of thumbKaidah praktis

Each layer has about 12·d² parameters (4d² attention + 8d² MLP) — so doubling the width quadruples the size, doubling depth doubles it. Generating one token costs roughly 2 FLOPs per parameter. The KV cache is 2·L·d values per token, so long contexts can need more memory than the weights.

Tiap lapisan punya sekitar 12·d² parameter (4d² attention + 8d² MLP) — jadi melipatgandakan lebar menaikkan ukuran empat kali, melipatgandakan kedalaman menaikkannya dua kali. Menghasilkan satu token memakan sekitar 2 FLOP per parameter. KV cache berukuran 2·L·d nilai per token, sehingga konteks panjang bisa butuh memori lebih besar daripada bobotnya.

Try this
  1. Pick GPT-2 small: ≈ 124 M parameters — matching the published figure. Untick "tie embeddings": the output matrix adds another 38 M.
  2. Pick 7B-class and switch precision from fp16 to int4: weights shrink from ~13 GB to ~3.4 GB — why quantised models fit on a laptop.
  3. Slide context T to the maximum on the 7B preset: the KV cache grows linearly and can exceed the weights.
Coba ini
  1. Pilih GPT-2 small: ≈ 124 jt parameter — cocok dengan angka terpublikasi. Hilangkan centang "ikat embedding": matriks keluaran menambah 38 jt lagi.
  2. Pilih kelas 7B dan ubah presisi dari fp16 ke int4: bobot menyusut dari ~13 GB ke ~3,4 GB — alasan model terkuantisasi muat di laptop.
  3. Geser konteks T ke maksimum pada preset 7B: KV cache tumbuh linear dan bisa melebihi bobotnya.

Training uses the same machinery: show the model a text, ask for the probability of each actual next token, and nudge the weights (gradient descent) to raise it — see the MLP from scratch, scaled up by many orders of magnitude.

Pelatihan memakai mesin yang sama: tunjukkan sebuah teks ke model, minta probabilitas tiap token berikutnya yang sebenarnya, lalu geser bobot (gradient descent) untuk menaikkannya — lihat MLP dari nol, diperbesar berorde-orde.
